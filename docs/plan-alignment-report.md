# 확정 기획 대조 및 기초 구현 점검 보고

점검일: 2026-09-25. 기준: 사용자가 제공한 최종 프로젝트 기획서 이미지 4장.

## 판정

PDF 업로드, 페이지 번호 보존, 핵심 영역 선별, 역할별 Agent Wrapper, JSON 검증·저장, Streamlit 5개 탭은 기초 구현되어 있다. 기획서와 달랐던 두 Extract의 순차 실행을 병렬 실행으로 수정했다.

현재 단계는 **실제 PDF를 전처리하는 Mock 프로토타입**이다. Business/Tech는 업로드 내용과 무관한 가상 JSON을 반환하며 Insight는 그 결과를 템플릿으로 종합한다. 실제 Studio API 통신과 AI 분석 정확도 검증이 남아 있으므로 실제 AI MVP 완성으로 판단하지 않는다.

## 이번 변경 파일

- `README.md`: 서비스 개요, 대상 사용자, 1차 MVP와 제품화 구분, 데이터 흐름, Agent 역할·Schema, 실행법, 현재 상태·한계·완료 조건으로 재구성했다.
- `app.py`: 두 Extract를 `ThreadPoolExecutor(max_workers=2)`에 먼저 제출하고 두 결과를 받은 후 Insight를 실행한다. PDF 처리·화면·결과 저장은 기존 흐름을 유지한다.
- `tests/test_workflow.py`: 기존 연결 테스트를 동시 실행 검증으로 강화했다. 두 Extract가 서로의 시작을 기다리는 Barrier를 사용해 순차 코드가 통과할 수 없도록 했다. 어느 Extract가 실패하든 Insight를 호출하지 않고 이전 결과를 보존하는 테스트도 추가했다.
- `agent_configs/README.md`: Business의 제품·서비스 필드 사용 지침을 명확히 했다.
- `agent_client.py`: 재편한 README에 맞게 모듈 설명의 과거 절 참조를 정리했다. 실제 통신 기능을 추가한 것은 아니다.
- `docs/mvp-report.md`, `docs/implementation-plan.md`: 과거 구현 기록임을 표시하고 현재 기준 문서로 연결했다. 당시 이력은 보존했다.
- `docs/plan-alignment-report.md`: 이 보고서.

작업 시작 전부터 수정되어 있던 전처리·Studio PDF 준비·UI·테스트 변경은 유지했다. `.env`, 실제 키, 기존 결과 파일은 변경하지 않았다. 추가 PDF 실행은 임시 출력 폴더에서 수행했다.

## 검증 결과

- 변경 전 전체 테스트 **40개 통과**.
- 병렬 실행 검증을 추가한 뒤 기존 순차 코드에서는 Barrier 대기 실패를 재현했다.
- 수정 후 전체 테스트 **41개 통과**: Agent/설정 8개, 전처리 8개, UI 10개, Studio PDF 전처리 7개, 워크플로 8개.
- 실제 전처리·세 Wrapper를 실행하고 통신 함수만 대체한 테스트에서 입력 분리, Agent ID 전달, 두 Extract 동시 실행, Insight의 두 JSON 수신, 저장을 확인했다.
- Business 실패와 Tech 실패 각각에서 Insight 미실행 및 기존 결과 파일의 바이트 보존을 확인했다. 기존 저장 도중 실패·복원 테스트도 통과했다.
- Streamlit AppTest에서 5개 탭, Mock 근거와 실제 원문 표시, 파일 교체·제거, 오류 후 재시도, Studio PDF 생성을 확인했다. AppTest 실행 시 bare-mode `ScriptRunContext` 경고가 있었으나 테스트 실패는 없었다. 실제 브라우저 직접 조작 검증은 수행하지 않았다.

로컬 PDF의 실제 전처리 → Mock 분석 → 임시 폴더 저장 결과:

| 입력 | 원본 페이지 | Business 선별 | Tech 선별 | Business 문자 | Tech 문자 | 안내 |
|---|---:|---:|---:|---:|---:|---|
| `data/sample_report.pdf` | 3 | 3 | 2 | 904 | 724 | 장 식별 대신 키워드 사용 경고 |
| 기아 정정 반기보고서(2026.09.16) | 309 | 46 | 36 | 62,786 | 55,843 | 책갈피 선별, 경고 없음 |

두 입력 모두 TXT 2개·JSON 3개를 저장했고 문자 제한에 걸리지 않았다. 로컬의 선별 PDF 두 개도 추가 실행했다. Business 선별 PDF를 다시 입력한 경우 직원 현황 식별 경고가 표시됐다. 이는 원본 전체 보고서 대신 부분 PDF를 다시 선별한 결과이므로 일반 사용에는 원본 보고서를 권장한다.

재현 명령:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

위 결과는 전처리와 Mock 워크플로 검증이며 실제 Studio 통신이나 공시 분석 정확도를 입증하지 않는다.

## 남은 우선순위

1. **실제 Agent 연결:** Studio의 endpoint·인증·요청/응답 형식과 세 Agent 설정을 확인하고 `agent_client.run_agent`에 통신·타임아웃·오류·JSON 처리를 구현한다. 현재 함수는 명시적으로 미구현 오류를 반환한다. 확인되지 않은 API 형식을 임의로 구현하지 않았다.
2. **근거와 품질 검증:** 실제 보고서에서 기업명·기간·숫자·단위·페이지를 대조하고, 인사이트가 입력 Fact에 근거하는지 평가한다. 현재 Pydantic 검증은 구조 검증이다. 일부 문자열·단일 수치 필드에 개별 출처가 없어 모든 Fact를 추적할 수는 없다.
3. **전처리 누락 평가:** 다양한 회사·보고서 형식에서 선별률을 확인하고, 120,000자 이후의 정보·복잡한 표·스캔 페이지 누락에 대응한다. OCR은 미지원이다.
4. **제품화 확장:** 실제 AI MVP 확인 후 OpenDART 자동 수집, 동일 기업·동일 기간 기준 전년도 비교와 Change Analysis를 구현한다.

현재 키·ID 설정만으로 실제 분석을 할 수는 없다. 병렬화는 호출 구조를 기획에 맞춘 변경이며 실제 원격 분석의 처리 시간·비용·품질 개선은 아직 측정하지 않았다.
